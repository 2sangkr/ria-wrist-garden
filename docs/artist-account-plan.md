# 모모갤러리 작가 로그인·작품 관리 구현안

작성일: 2026-10-10
상태: 첫 구현과 로컬 검증 완료. Google 제공자 설정, 실제 서비스 데이터 마이그레이션 및 운영 전환은 미완료.

## 목표

기존 공개 작가 페이지와 작품 등록 화면을 재사용한다. Google로 로그인한 승인 작가에게만 작품 올리기·수정·삭제 기능을 제공한다. 방문자는 지금처럼 로그인 없이 감상한다.

## 첫 구현 범위

- Google 로그인, 로그인 결과 처리, 로그아웃.
- 작가 신청, 승인 대기, 운영자 승인·거절.
- 기존 작가 페이지에 해당 관리자만 볼 수 있는 작품 올리기 버튼.
- 작품 상세 화면에 해당 관리자만 볼 수 있는 수정·삭제 버튼.
- 기존 등록 폼을 재사용한 등록·수정 화면.
- 휴지통 이동 및 복원. 첫 버전에서는 자동 영구 삭제를 하지 않는다. 보관 기간 및 영구 삭제 정책은 별도 확정한다.
- 운영자가 기존 작가에 로그인 계정을 연결하는 기능.
- 한 로그인 계정이 여러 작가를 관리할 수 있는 구조. 여러 작가가 연결되어 있으면 '내 작품'에서 작가를 선택한다.

## 화면과 이용 흐름

1. 공개 작가 및 작품 페이지는 기존 디자인을 유지한다.
2. 사이트 메뉴에 로그인 / 내 작품을 추가한다.
3. Google 로그인 후 연결된 작가가 있으면 해당 작가 페이지로 이동한다.
4. 연결된 작가가 없으면 작가 신청 또는 승인 대기 상태를 표시한다.
5. 등록·수정 성공 후 기존 작품 상세 또는 작가 페이지로 돌아간다.
6. 삭제 확인 대화상자에서 공개 목록에서 숨겨지고 복원 가능함을 안내한다.

신청 정보: 활동명, 작품 활동 소개, 유입 경로(선택), 연락용 이메일. 연락용 이메일과 로그인 계정은 별개로 저장한다. 아이의 작품은 보호자 계정이 관리할 수 있다.

## 로그인과 권한

Supabase Auth의 Google 로그인을 사용한다. Gmail이 아닌 주소도 Google 계정이면 사용할 수 있다. Google 계정이 없는 신청자를 위한 이메일 인증 방식은 후속 범위로 둔다.

Google 로그인은 신원 확인을 담당한다. 작품 변경 권한은 사이트와 데이터베이스에서 별도로 확인한다.

- 계정의 고유 사용자 ID를 기준으로 권한을 연결한다. 이메일 문자열 또는 활동명 일치만으로 자동 연결하지 않는다.
- artists는 공개 작가 정보만 유지하고, 계정 연결과 신청자 연락처는 비공개 테이블에 둔다.
- artist_memberships: artist_id, user_id, 역할. 두 ID 조합은 중복 불가.
- artist_applications: 신청자 user_id, 활동명, 소개, 연락 이메일, 유입 경로, 상태, 처리 이력.
- 운영자 권한은 서버에서 관리하는 별도 테이블로 지정한다. 사용자 수정 가능한 프로필 필드를 권한 판단에 사용하지 않는다.
- 모든 변경 API에서 검증된 로그인 사용자와 작가 연결을 확인한다. 화면 버튼 표시만으로 보호하지 않는다.
- RLS로 일반 사용자에게 본인 신청·본인 연결·본인 작품 변경만 허용한다. 승인·계정 연결은 운영자만 가능하다.
- Storage 업로드·변경·삭제에도 동일한 소유권 검증을 적용한다. 공개 사진 열람과 파일 변경 권한은 구분한다.
- 서비스 역할 키는 서버 전용으로 유지한다. 이 키를 쓰는 서버 경로도 매번 권한 검증을 수행한다.
- 쿠키 기반 로그인 변경 요청에는 동일 출처 검증을 적용하고, 로그인 돌아갈 주소는 내부 허용 경로만 받는다.

## 작품과 휴지통

works에 deleted_at을 추가한다. 공개 조회와 통계는 삭제된 작품을 제외한다. 휴지통 조회는 해당 작가 관리자와 운영자에게만 허용한다.

휴지통 이동 시 사진 파일은 지우지 않는다. 공개 Storage의 사진 주소를 이미 아는 사람이 파일을 볼 수 있다는 한계가 있으므로, 공개 목록에서 숨기기와 파일 접근 차단을 같은 의미로 안내하지 않는다. 완전 비공개 보관이 필요하면 별도의 비공개 저장 방식으로 설계한다.

사진 교체는 새 파일 업로드와 DB 저장이 성공한 뒤 기존 파일을 정리한다. DB 저장 실패 시 새 파일을 정리한다. 이미지 종류·용량·제목·날짜·나이 등을 서버에서도 검증한다.

## 기존 작가와 링크 전환

- 기존 artists와 works ID, 공개 주소, 작품 사진을 유지한다.
- 기존 작가에게 로그인 계정을 확인받고 운영자가 연결한다. 현재 Evan 신청 이메일이 Google 계정인지 확인되지 않았으므로 자동 연결하지 않는다.
- 연결과 본인 등록·수정·복원 확인이 끝난 뒤 기존 토큰 업로드를 종료한다.
- 전환 전에는 기존 링크가 계속 업로드 권한을 가진다는 사실을 기록하고, 로그인 도입만으로 보안 전환이 끝났다고 판단하지 않는다.
- 기존 /upload/[token]은 종료 후 로그인 안내로 전환하고 /api/upload의 토큰만으로 등록하는 경로도 차단한다.
- 텔레그램 /link도 로그인 도입 후 공통 로그인 주소를 안내하도록 변경한다.
- 사이트 신청 기능과 운영자 승인 기능이 준비되기 전까지 Google Forms를 유지한다.

## 구현 순서

1. 데이터베이스 및 Storage 백업을 확보하고 복구 가능 여부 확인.
2. 데이터 마이그레이션, 권한 규칙, 로그인 기반 공통 서버 인증 구현.
3. Google 로그인 화면 및 Supabase·Google 제공자 설정.
4. 기존 작가 페이지의 관리 버튼과 등록·수정·휴지통 구현.
5. 신청·승인 및 기존 작가 계정 연결 화면 구현.
6. 미리보기 환경에서 두 개의 계정으로 권한 테스트.
7. 운영 계정 및 기존 작가 연결, 운영 전환, 토큰 등록 종료.

로컬 코드 변경만으로 Google 로그인은 활성화되지 않는다. Google Cloud의 OAuth 설정과 Supabase 제공자 설정, 운영·미리보기 로그인 복귀 주소 등록이 필요하다. 비밀값은 문서나 화면 보고에 출력하지 않는다.

## 필수 검증

- 로그인하지 않은 사람은 공개 감상만 가능하고 변경 요청은 거부된다.
- 승인 대기 사용자는 작품을 등록할 수 없다.
- 작가 A는 자신의 작품을 등록·수정·삭제·복원할 수 있다.
- 작가 A가 작가 B의 ID를 요청에 넣어도 DB 및 Storage 변경은 거부된다.
- 신청자가 스스로 승인 상태나 운영자 권한을 바꿀 수 없다.
- 운영자만 신청 승인 및 기존 작가 계정 연결이 가능하다.
- 휴지통 작품은 공개 페이지·메타데이터·통계에서 제외된다.
- 기존 작가 및 작품 주소, 사진이 유지된다.
- 로그아웃 후 변경 요청이 거부된다.
- 전환 완료 후 기존 토큰만으로 업로드할 수 없다.

- src/app/upload/[token]/UploadForm.tsx: 기존 등록 폼.
- src/app/api/upload/route.ts: 현재 토큰 기반 등록 처리. 로그인 권한 확인으로 교체 대상.
- src/lib/supabase.ts: 기존 Supabase 연결.
- src/proxy.ts: 계정 기능 활성화 시 이전 비밀번호 관리자 API를 종료하고, 로그인 세션을 갱신한다. 기능 비활성화 시 기존 보호 동작을 유지한다.
